## [Unreleased]

### Added

- `Convert-Image`: Converts every image Magick.NET can read (HEIC/HEIF, JPEG, PNG, WebP, AVIF, TIFF, ...) to Jpeg, Png, WebP, Avif, Jxl (JPEG XL), Tiff, Bmp or Gif. `-Path` with wildcards, `-LiteralPath` (pipeline input from `Get-ChildItem` and `Get-ImageInfo`, folders are skipped, a file given twice is converted once), `-DestinationPath`, `-Quality` (lossy formats Jpeg, WebP, Avif, Jxl), `-Force`, `-WhatIf` and `-Confirm`. Applies the EXIF orientation (and then removes the EXIF thumbnail and updates the XMP orientation and pixel dimensions) and keeps the metadata the output format can carry unless `-StripMetadata` is used, which removes EXIF (including GPS), XMP, IPTC and comments but keeps the ICC colour profile (in PNG output only as iCCP chunk, with an RGB colour type when an RGB profile comes with neutral grey pixels, so readers accept it). Warns when Tiff, Gif or Bmp output drops EXIF data. CMYK sources stay CMYK in Jpeg and Tiff output and are converted to sRGB through their profile for the other formats. Lossy Jxl output (`-Quality` below 100) stores no ICC profile, so the pixels of a source with one (Display P3, Adobe RGB) are converted to sRGB first and keep their look; a damaged profile or one made for other pixels (a grey profile in a colour image) is ignored, as viewers do; `-Quality 100` keeps the profile. Transparent pixels are placed on white in Jpeg output (paper white for a CMYK image); the other formats keep the alpha channel, also Tiff output of a palette PNG with up to 16 colours. Sources with several frames (animated GIF/WebP, multi-page TIFF, HEIC with several images) are converted from their first frame with a warning; a source ImageMagick reports as damaged (e.g. a truncated JPEG, or an animated GIF cut off after its first frame) is converted with the warning `The image may be damaged (<reasons>): <path>`. Returns the written files as `Get-Item` does, so they can be piped into the next cmdlet also when their names contain `[` or `]`. Writing HEIC is not supported (the bundled Magick.NET build has no HEVC encoder).
- `Convert-Image` writes through a temporary file in the target folder, so a failed or stopped (Ctrl+C) conversion leaves neither a truncated file nor the temporary file; file names with `%` and target names up to the file system limit work. It never overwrites the source file or a file written earlier in the same call (also not with `-Force`), compared by file identity, so a junction, a symbolic link, a subst or mapped drive, a UNC path, a short 8.3 name or a case-insensitive volume on Linux do not get around it; `-Force` replaces read-only and hidden files and keeps their attributes when the file cannot be replaced.
- `ConvertTo-Jpeg`, `ConvertTo-Png`, `ConvertTo-WebP`, `ConvertTo-Avif`, `ConvertTo-JpegXL`: Shortcuts for `Convert-Image -Format Jpeg/Png/WebP/Avif/Jxl` with the same parameters minus `-Format` (`ConvertTo-Png` has no `-Quality`). All files of one call, also from the pipeline, go through a single `Convert-Image` call, so duplicate targets are detected and `-WhatIf`, `-ErrorAction`, `-ErrorVariable`, `-OutVariable`, `-PipelineVariable` and `$?` behave like `Convert-Image`. A source already in the target format (e.g. `ConvertTo-Jpeg a.jpg`) needs a `-DestinationPath`; otherwise it gets a `TargetIsSource` error. The shortcuts call the module's own `Convert-Image`, also when the session defines an alias or a function of that name.
- `ConvertFrom-Heic`: Converts HEIC/HEIF images through `Convert-Image` (default format Jpeg) and rejects files without the extension `.heic`, `.heif` or `.hif`, except the files the call writes itself (`Get-ChildItem -Recurse` into a `-DestinationPath` inside the tree).
- All cmdlets report a failed file as non-terminating error with a stable error id (`PathNotFound`, `InvalidWildcardPattern`, `UnsupportedProvider`, `NotHeicFile`, `TargetIsSource`, `DuplicateTarget`, `TargetExists`, `ConfirmationFailed`, `ImageReadFailed`, `ImageWriteFailed`) and the source file as target object (for `PathNotFound`, `InvalidWildcardPattern` and `UnsupportedProvider` the input as given, one error per input): `$?` is `$false` after a failed file, `-ErrorVariable` holds one record per failure and `-ErrorAction Stop` stops at the first one. For a wildcard pattern that matches nothing, `PathNotFound` says so, that wildcards skip hidden files and, for a pattern with `[` or `]`, that these are wildcard characters; an invalid pattern is `InvalidWildcardPattern` whether or not a file of that name exists. `ConfirmationFailed` reports a `-Confirm` that the host cannot ask (e.g. `pwsh -NonInteractive`). A `-DestinationPath` that cannot name a folder (`InvalidDestinationPath`, `UnsupportedProvider`, `DestinationNotDirectory`, also for white space only and for a junction or symbolic link whose target is missing; target object the `-DestinationPath` value) stops the whole call with one terminating error before any file is read, also with `-WhatIf`; the shortcuts report it with their own name. A destination folder that cannot be created or written to fails each file with `ImageWriteFailed`.
- All cmdlets follow the preference variables of their caller (`$WhatIfPreference`, `$ConfirmPreference`, `$ErrorActionPreference`, `$WarningPreference`, `$InformationPreference`, `$VerbosePreference`, `$DebugPreference`) like compiled cmdlets, also when a script or function sets them in its own scope, e.g. a function with `SupportsShouldProcess` called with `-WhatIf`; a common parameter given to the cmdlet wins.
- `Get-ImageInfo`: Returns format, dimensions, orientation, camera make/model, date taken and file size of HEIC/HEIF and other images; `-Path` with wildcards or `-LiteralPath`, folders are skipped; an image without orientation tag is reported as `TopLeft`; a damaged image (e.g. a truncated JPEG) gets the same warning as in `Convert-Image`; a file given twice is described once. The objects (`PSImageConverter.ImageInfo`) carry a `PSPath` property, hidden from the default view, so they can be piped into the conversion cmdlets (`Get-ImageInfo *.heic | Where-Object Width -GT 4000 | ConvertTo-Jpeg`); cmdlets that take `-Path` by property name, such as `Get-Item`, bind their `Path` property as a wildcard pattern instead.
- Bundles Magick.NET (Q8, AnyCPU) for Windows (x64, arm64), Linux (x64, arm64, musl-x64) and macOS (x64, arm64). The libraries are downloaded from nuget.org at build time by the `Get_MagickNet` build task.
- Requires PowerShell 7.4 or later; the native library is loaded through the same DllImport resolver on every platform, also when several runspaces (`Start-ThreadJob`, `ForEach-Object -Parallel`) import the module at the same time.
- Sampler build pipeline with GitHub Actions: test matrix (PowerShell 7 on Windows, Linux and macOS) and publishing to the PowerShell Gallery from `main` via the `release` environment. After a release, `Create_ChangeLog_GitHub_PR` opens a pull request with the CHANGELOG update.
- Every push to `dev` publishes a pre-release (`<version>-previewNNNN`) to GitHub and the PowerShell Gallery through the Sampler workflow `publish_prerelease`.
